# 相似度阈值标定 —— 真实算法说明

## 命中/未命中"分布图"怎么看(可视化补充)

界面会画两个直方图:「命中分数分布」和「未命中分数分布」。

### 什么是"命中分数分布"
把评估集里每个"正确答案应该被找到"的问题,实际检索后,**正确那个块的相似度得分**挨个收集起来画图。因为每个问题命中分数有高有低(问得准就高、问得含糊就低),所以是一组分散的数。

```
问题A "怎么安装"   → 正确答案块 0.61
问题B "怎么配置"   → 正确答案块 0.68
问题C "出错了?"   → 正确答案块 0.78
问题D "问得含糊"   → 正确答案块 0.52
```

### 它解决的三个问题
1. **验证阈值会不会误杀正确答案(最关键)**:如果命中团全都 ≥ 阈值(如 0.522),阈值安全;如果有一批命中分数在阈值之下,设这阈值会误杀,正确答案被滤掉。
2. **看数据健康度**:分布"高而集中"(全在 0.6–0.8)→ 文档/提问质量高;分布"低而散"→ 可能切块差或提问含糊,去查坏例。
3. **和未命中分布对比,正是算法取中间值的依据**:命中团(偏高)+未命中团(偏低)中间的空隙 = 理想阈值位置,0.522 就从这两团四分位中点算出。

### 一张表记住分工
| | 命中分布 | 未命中分布 |
|---|---|---|
| 代表 | 正确答案被找到时的分数 | 正确答案没找到时(噪声)的分数 |
| 作用 | 防止阈值**误杀真答案** | 防止阈值**放过太多噪声** |
| 决定 | 看它下限在哪,别卡太高 | 看它上限在哪,别放太低 |

一句话:**命中分布告诉你会不会误伤,未命中分布告诉你会不会漏放;阈值就是平衡这两者的中间线。**

---

## 一句话定位

推荐阈值 = **命中分数下四分位 与 未命中分数上四分位的中间值**。它落在"真相关"和"噪声"两团分数之间的空隙,既不过度误杀正确答案、也不放过太多噪声。

## 完整的 4 步算法(对应 `core/optimize.py` 的 `calibrate_threshold`)

```
第1步 对评估集每个问题跑检索,取 top-k 的相似度分数
第2步 把分数分成两团:
       · 命中分数   = 正确答案真被检索到的那些分数
       · 未命中分数 = 正确答案没被检索到的那些分数
第3步 各取一个"靠近分界的四分位"做锚点:
       lo = 命中分数的 25% 分位（命中团里偏低的分界）
       hi = 未命中分数的 75% 分位（未命中团里偏高的分界）
第4步 推荐值 = round((lo + hi) / 2, 3)
```

> 代码依据:
> `lo = statistics.quantiles(hit_scores, n=4)[2]`(不足 4 条时退化为 `min`)
> `hi = statistics.quantiles(miss_scores, n=4)[2]`(空时退化为默认)
> `rec = (lo + hi) / 2`

## 常见误区澄清

- ❌ **不是**用 count / mean / std / 50% 等全部统计量算出阈值。
- ✅ 只用到 **25%(命中下四分位)** 和 **75%(未命中上四分位)** 两个输入,取平均。
- `.describe()` 输出的 count/mean/std/25/50/75% 只是**界面附带的体检展示**,不进公式。
- 所以界面上看到的顺序是:**推荐值先算出来 → 再用 describe() 给两组分数做展示**,两者不是"由展示算出推荐值"。

## 面试口语话术(可直接用)

> "我用评估集跑出每个问题在检索里的相似度分数,分成『命中』和『未命中』两团;各取靠分界的四分位点,取它们的中间值作为推荐阈值,让阈值落在两团分数之间的空隙里——既不过度误杀真相关、也不放过噪声。"

## 换源/换模型时要注意

- 0.35 只是通用初值,**换 embedding 模型或换文档格式后,分数区间会变,0.522 也可能不再适用**。
- 正确做法:每次换源/换模型后,**重新跑一次"标定相似度阈值"**,用新数据重标,而不是死守旧值。

## 判定这个阈值靠不靠谱(看两栏统计)

| 观察 | 含义 | 结论 |
|---|---|---|
| count 太少(如 <4) | 样本不足 | 阈值不可信,先补评估集 |
| 命中团 25% 明显高于推荐值 | 真相关分数普遍更高 | 阈值可以再收严 |
| 命中团 50% 低于推荐值 | 不少正确答案被阈值误杀 | 阈值太高,不该用 |
| std 很小 | 分数很一致 | 区分度可能不足 |
