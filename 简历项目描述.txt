简历项目描述 —— RAG 智能客服问答系统
====================================

针对 AI 产品经理岗位，从 0 到 1 打造的 RAG 智能客服问答系统。
以下为按 PM 工作流程组织的整合版，后附三个压缩版本备选。
（2026-08-29 更新至最新项目版本：评估集扩容至 126 条 + Rerank 精排落地）

------------------------------------------------------------
【项目亮点速览】（最新版）
------------------------------------------------------------
1. 端到端 RAG 问答系统：多格式文档源 → 转码 → 结构感知切块 → 向量检索 → Rerank 精排 → 带引用生成
2. 多格式文档源接入：docx / pdf / xlsx / pptx 一键转 Markdown 入库，不依赖在线爬取，
   贴合真实客服文档场景
3. 量化评估体系：126 条评估集（自动基线 + 真实口语化 + 难例/边界例 + 语义去重）；召回率、引用准确率
   提升至 92.00% / 90.40%；坏例分析闭环 + 双口径评测记录
4. 数据驱动优化：坏例溯源定位"切块粒度 / 泛查询 / 指标判定"三类根因并逐类修复；评估集从 54 条扩容到
   126 条、指标如实回落（不掩盖短板）后，经"查询改写 + 引用后校验 + Rerank 交叉编码器精排"回升——
   召回率 87.20%→92.00%、引用准确率 85.60%→90.40%、坏例 18→12；全程不改判定规则注水、保留新旧双口径

------------------------------------------------------------
一、需求洞察与澄清
------------------------------------------------------------
客服场景普遍存在"知识散落于手册/FAQ/聊天记录、回答慢、口径漂移"的痛点，尤其致命的是
效果好坏完全无法量化。面对模糊诉求，我没有直接动手，而是先设计情境题追问交付形态——
给谁用、知识源从哪来、最终要什么形态，据此收敛出"可上传文档、可自我评估"的明确产品定位，
并确定"先跑通 MVP、再数据驱动迭代"的节奏。

------------------------------------------------------------
二、产品定义
------------------------------------------------------------
将定位写成可执行的规格文档作为开发蓝图：明确技术选型（DeepSeek + bge-m3 + bge-reranker-v2-m3 +
Chroma + markitdown）、目录结构、MVP 拆解与验收标准；并预先设计"评估集版本快照"机制——每次评测
绑定当时的文档源与参数，保证"改前 vs 改后"是同一套考卷对比，为迭代的可信度埋下伏笔。

------------------------------------------------------------
三、技术方案落地
------------------------------------------------------------
主导端到端流水线搭建：多格式文档源（docx/pdf/xlsx/pptx）一键转 Markdown → 结构感知切块
→ 向量检索 → 引用生成。针对真实客服文档多为 Word/PDF/Excel 的场景，设计"转换产物保留
标题层级 + 无标题兜底补标题"的转码契约，使新增格式无需改动核心入库逻辑即可接入。
同时以相似度阈值闸门防幻觉，让每条答案可溯源、可解释。语料放大后，在检索层引入 Rerank
（交叉编码器 bge-reranker-v2-m3）精排，针对性解决双塔向量检索"同章节高相关块互相竞争"的
排序短板。

------------------------------------------------------------
四、数据驱动的评估体系
------------------------------------------------------------
不靠肉眼判断"答得好不好"，而是让 AI 根据实际入库文档自动生成评估集（问题+标准答案+应命中
原文），本人抽检后手工补充真实口语化问题，并把评估集从 54 条扩容到 126 条——新增难例/边界例、
按语义相似度去重（159→126）；定义召回率、引用准确率、坏例三大指标；通过"命中 vs 未命中"
分数分布标定相似度阈值。把"系统好不好"从主观感受变成可量化、可复现的数据；扩容后的指标回落
如实记录、不掩盖——样本越大、题越难，指标才越可信。

------------------------------------------------------------
五、基于坏例的迭代优化
------------------------------------------------------------
通过坏例归类定位真实缺陷并逐类修复：
①切块粒度——"会员体系"大块把多个知识点塞在一起导致语义稀释，实施细粒度切块后目标答案的
  检索命中从第 7 名提升至第 1 名；
②指标判定——发现切块重叠让同一句出现在相邻两块、评估映射选错块导致指标误判，修正映射
  （选内容最相似块）并采用双口径记录，小集指标如实提升至 98.15%；
③泛查询与排序短板——评估集扩容到 126 条后指标如实回落，定位到 bi-encoder 余弦排序能力不足：
  先试查询改写 + 引用后校验（收益有限，如实记录），再针对性启用 Rerank 交叉编码器精排
  （bge-reranker-v2-m3），召回率 87.20%→92.00%、引用准确率 85.60%→90.40%、坏例 18→12；
  过程中还修复了"Rerank 精排顺序被 bi-encoder 分数重排覆盖"的排序缺口，以及模型依赖旧 API
  崩溃被静默吞掉导致"Rerank 前后没变化"的工程坑。
全程坚持不改判定规则注水、保留新旧口径，形成"评估→坏例→定位→修复→口径可信"的完整闭环，
而非盲目调参。

------------------------------------------------------------
补充：面试官想看的三点
------------------------------------------------------------
针对 AI 产品经理岗，以下三点是核心竞争力，已在整合版中埋入：

1. 需求澄清能力 —— "用情境题追问交付形态"，这是 PM 基本功。
2. 数据驱动 —— "不拍脑袋，用指标和坏例说话，甚至用数据说服自己不做某件事"，
   这是 AI PM 与普通 PM 的分水岭。
3. 技术理解力 —— 能讲清切块、向量检索、阈值、Rerank（双塔召回 + 交叉编码器精排）、多格式转码，
   并亲手排查过"Rerank 静默失效 / 精排顺序被覆盖"这类工程坑，说明能和工程师平等对话，
   这是 AI PM 的核心竞争力。
